Seis elementos para um bom prompt:

Papel: Atue como um analista de requisitos senior.
Contexto: Uma pessoa organiza suas atividades.
Objetivo: Especificar um MVP de tarefas.
Escopo: CRUD, status e filtros simples.
Restrições: Sem login nem funções extras.
Saída: Lista de requisitos + testes.


Como um analista de resquisitos, crie os requisitos para criar um sistema web MVP(Produto minimamente viável) onde poderá controlar as tarefas que uma pessoa tem à fazer. Não precisa fazer login. Que possa realizar o CRUD. Quero uma lista de requisitos e os testes.

Seis informações que precisam para chegar no Lovable:

Usuário: Estudante organizando a semana.
Objetivo: Visualizar e gerenciar as tarefas.
Funcionalidades: Criar, editar, concluir, excluir, filtrar.
Estados: Vazio, carregando, erro, sucesso.
Design: Simples, responsivo, acessível.
Limites: Sem login e sem serviço de dados novo.

Início de prompt para o Lovable:

Tenho uma especificação de MVP de lista de tarefas.
Transforme-a em um prompt para gerar somente o front-end no Lovable.
Inclua: usuário, problema, fluxo, componentes, estados de interface,
responsividade, acessibilidade e restrições do escopo.
NÃO adicione autenticação, serviços de banco ou integrações externas.
Use dados simulados claramente identificados.
Organize a resposta em: objetivo, páginas, comportamentos, limites
e critérios de aceitação visual.
Antes do prompt final, aponte lacunas ou contradições.
